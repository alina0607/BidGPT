## 1. 一句話

讓神經網路像人一樣，**一筆一筆畫出線條圖**（向量圖），而不是一格一格產生像素；並公開 QuickDraw 筆畫資料集。

## 2. 日常類比

你在電話上指揮朋友畫一隻貓，朋友看不到你的圖，只聽得到指令：
「往左下走 15、往上 78……抬筆……跳到右邊……畫完了。」

我們資料裡第 7372 張貓（實測）就是這樣一份「指令清單」：**15 個點、3 筆**。
第一筆 6 個點（左耳和左臉），第二筆 7 個點（右耳和右臉），第三筆只有 2 個點（一小撇）。

Sketch-RNN 學的就是**當那個聽指令的朋友**：聽完前面所有指令，猜下一句指令是什麼。
猜完就照著畫，再把自己剛剛畫的那一步當成「前一句」，接著猜下一句。

論文的完整版還多一個人：**先讓另一個人看完整張圖，把它濃縮成一張 128 格的「描述卡」**，再交給畫的人。
這張卡就是後面說的潛在向量（latent vector）z。

## 3. 為什麼需要它

| 之前 | 卡在哪 |
|---|---|
| 圖片生成幾乎都做**像素圖**（GAN、VAE、自迴歸模型），而且多半是低解析度 | 人畫畫不是在填格子，而是「往哪走、何時抬筆、何時停」的動作序列。像素圖丟掉了筆畫順序 |
| 向量線條的生成很少：HMM 合成線條；Graves 2013 用 RNN 生成手寫字；Ha 2015、Zhang 2016 生成漢字筆畫 | 都是窄範圍（手寫字、漢字），沒有「很多種日常物品」 |
| 公開資料集很小：Sketch 20K 張、Sketchy 70K 張 | 這篇的 QuickDraw **每一類**就有 70K 訓練張（§3.1） |
| 「何時停筆」：之前的漢字模型替三種筆狀態的損失手調權重，例如 (1, 10, 100) | 作者覺得這招不漂亮，而且在多樣的類別上不夠用（§3.2） |

## 4. 方法（照論文章節順序）

### 4.1 資料格式：stroke-5（§3.1，附錄 §1）

一張圖 = 一串點，每個點是 5 個數字 **(Δx, Δy, p1, p2, p3)**：

| 符號 | 意思 |
|---|---|
| Δx, Δy | 這一點**相對於上一點**移動了多少（位移，offset）。不是絕對座標 |
| p1 = 1 | 筆還在紙上：這一點和下一點之間要畫線 |
| p2 = 1 | 這一點之後**抬筆**：跟下一點之間不畫線 |
| p3 = 1 | **畫完了**：這一點和之後的點都不畫 |

p1、p2、p3 三個裡永遠只有一個是 1，這種寫法叫 one-hot（獨熱編碼）。

**實測：第 7372 張貓換成 stroke-5**（Δ = 這一點 − 上一點；第 1 點相對原點 (0,0)）：

| # | 絕對座標 (x, y) | stroke-5 |
|---|---|---|
| 1 | (18, 138) | (18, 138, 1, 0, 0) |
| 2 | (3, 60) | (−15, −78, 1, 0, 0) |
| 3 | (0, 0) | (−3, −60, 1, 0, 0) |
| 4 | (5, 4) | (5, 4, 1, 0, 0) |
| 5 | (53, 68) | (48, 64, 1, 0, 0) |
| 6 | (84, 105) | (31, 37, **0, 1**, 0) ← 第一筆結束，抬筆 |
| 7 | (148, 87) | (64, −18, 1, 0, 0) ← 筆在空中移過去，**這段不畫線** |
| 8–12 | … | … |
| 13 | (231, 141) | (−15, 52, **0, 1**, 0) ← 第二筆結束 |
| 14 | (76, 103) | (−155, −38, 1, 0, 0) |
| 15 | (82, 99) | (6, −4, **0, 1**, 0) |
| 16 | — | (0, 0, 0, 0, **1**) ← 結束 |

自己驗算：第 7 點 = (148 − 84, 87 − 105) = (64, −18)。第 6 點的 p2 = 1，所以第 6 點和第 7 點之間沒有線。

資料處理（附錄 §1）：
- 筆畫用 Ramer–Douglas–Peucker 演算法簡化，參數 ε = 2.0。**我們下載的 `simplified` 檔就是同一種簡化**（`strokes.py` 開頭的說明）。
- 位移 (Δx, Δy) 會除以同一個比例，讓訓練集的標準差變成 1。

### 4.2 模型：序列到序列的變分自編碼器（Sequence-to-Sequence VAE）（§3.2）

分成兩半：**編碼器（encoder）** 把整張圖讀成描述卡 z，**解碼器（decoder）** 照 z 一步一步畫出來。

**編碼器**是雙向 RNN（bidirectional RNN）：一個 RNN 從頭讀到尾，另一個從尾讀到頭，最後把兩個狀態接起來，叫 h（式 1）。
接著（式 2）：

```
μ = Wμ h + bμ        σ̂ = Wσ h + bσ        σ = exp(σ̂ / 2)        z = μ + σ ⊙ N(0, I)
```

- μ（mu）：描述卡的「中心值」，128 個數字。
- σ（sigma）：每一格允許晃動多少。用 exp 是為了保證它不是負的。
- N(0, I)：128 個標準常態亂數。
- 所以 **同一張圖每次編出來的 z 都會稍微不同**：中心是 μ，加上一點隨機晃動。

**解碼器**是自迴歸 RNN（autoregressive：每一步都依賴前一步的輸出）。
它的起始狀態由 z 算出來：`[h0; c0] = tanh(Wz z + bz)`。
每一步 i 的輸入是「上一點 S_{i−1}」接上 z；第 0 步的「上一點」固定是 (0, 0, 1, 0, 0)。

每一步輸出一個向量 y_i，裡面裝的是**下一點的機率分布**，不是下一點本身（式 3–7）：

- **(Δx, Δy) 用高斯混合模型（Gaussian mixture model, GMM）表示**：M 個二維常態分布（鐘形）加權相加。
  每個鐘形有 5 個參數 (μx, μy, σx, σy, ρxy)：中心兩個、寬度兩個、相關係數 ρ 一個（ρ 用 tanh 壓到 −1 到 1）。
  另外還有 M 個混合權重 Π，總和為 1。
  - 白話：下一步可能有好幾個合理去向，例如「往左畫耳朵」和「往右畫鬍鬚」。一個鐘形只有一個中心，
    所以用 M 個鐘形，每個管一種可能。
- **(p1, p2, p3) 用三選一的機率 (q1, q2, q3)** 表示，經過 softmax，總和為 1。
- 輸出長度 = 5M + M + 3 = **6M + 3**。論文用 M = 20（附錄 §3），所以每一步輸出 **123** 個數字。

**最難的部分：何時停筆（§3.2，作者原話是 "a key challenge"）。**
三種筆狀態的次數非常不平均。

**實測（15,500 張貓）**：

| 筆狀態 | 次數 | 每張圖平均 |
|---|---|---|
| p1（繼續畫） | 795,172 | 51.3 |
| p2（抬筆） | 153,642 | 9.9 |
| p3（結束） | 15,500 | 1 |

模型如果偷懶永遠猜 p1，大部分時候都猜對，卻永遠學不會停。

舊做法是手調權重 (1, 10, 100)。這篇的做法是：**把每張圖都補長到 N_max**（訓練集裡最長那張的長度），
補上去的點全部標成 (0, 0, 0, 0, 1)，而且筆狀態的損失 L_p 算滿整個 N_max。
- 實測：如果 N_max = 200，每張貓平均有 **139.0 個 p3 標籤**，比 p1 的 51.1 還多，比例整個倒過來。
- ⚠️ 我自己的觀察，論文沒有講：這 139 個裡只有**第一個**是真正難的（「現在該停了嗎？」）。
  其餘都是「已經停了，下一步還是停」，非常好猜。
- ⚠️ 論文**沒有給任何數字**比較這招和 (1, 10, 100) 權重法，只說 "more robust"。

**取樣與溫度（temperature）τ（式 8）**：產生圖時，每一步從機率分布裡抽一個點，再把抽到的點當成下一步的輸入。
抽到 p3 = 1，或長度到達 N_max，就停。抽之前先用 τ 調整：

```
q̂k → q̂k / τ        Π̂k → Π̂k / τ        σx² → σx² τ        σy² → σy² τ
```

- softmax 之前的分數除以 τ。τ < 1 時差距會被放大，最可能的選項更突出。
  實測：分數 (3, 1, −1) 在 τ = 1 時機率是 (0.867, 0.117, 0.016)；τ = 0.5 → (0.982, 0.018, 0.0003)；τ = 0.1 → (1.0, 0.0, 0.0)。
- 鐘形的變異數乘上 τ。例如 σ = 10 px、τ = 0.25 → σ² = 100 × 0.25 = 25 → σ = 5 px，抖動減半。
- τ → 0 時完全不隨機，永遠挑最可能的那一點。論文說 τ 通常設在 0 到 1 之間。

### 4.3 無條件生成（unconditional generation）（§3.3）

把編碼器拿掉，只留解碼器：起始狀態全是 0，每一步只輸入上一點，沒有 z。
這就是一個純粹的「接著畫」模型。
⭐ **這就是我們畫圖 GPT 的祖先**：RNN 換成 Transformer、GMM 換成 1,000 個標準動作，再加上類別 token。

### 4.4 訓練（§3.4，附錄 §2）

```
Loss = L_R + w_KL · L_KL                    （式 11）
L_R  = L_s + L_p                            重建損失（reconstruction loss）
```

- **L_s**（式 9）：真實的那一步 (Δx_i, Δy_i)，在模型給的高斯混合分布下有多大的機率密度；取 log、加負號、加總，
  **只加到這張圖真正的長度 N_s**，最後除以 N_max。
- **L_p**（式 9）：筆狀態的交叉熵 −Σ p_k log q_k，**加滿整個 N_max**，同樣除以 N_max。
- **L_KL**（式 10）：`−(1/(2N_z)) · Σ(1 + σ̂ − μ² − exp(σ̂))`，量的是「描述卡 z 的分布離標準常態有多遠」。
  白話：逼描述卡不要亂寫，要落在一個整齊的範圍裡。這樣**隨便抽一張卡**交給解碼器，也能畫出像樣的圖。
- **w_KL** 是兩者的拉鋸：w_KL → 0 變成普通自編碼器，重建更準，但卡片空間不整齊。

附錄 §2 的兩個訓練技巧：

```
η_step     = 1 − (1 − η_min) · R^step
Loss_train = L_R + w_KL · η_step · max(L_KL, KL_min)        （附錄式 4）
```

- **KL 退火（annealing）**：η 從 η_min（0 或 0.01）慢慢升到 1，讓模型先專心學畫，再管卡片整不整齊。
  論文設 R = 0.99999。可以自己驗算：η_min = 0 時，第 100,000 步的 η = 1 − 0.99999^100000 ≈ 1 − e^(−1) ≈ **0.632**。
- **KL 下限 KL_min**：L_KL 低於 KL_min 就不再壓它。論文用 0.20。作者觀察到 L_KL 從 > 1.0 降到約 0.3 時，畫質明顯變好；
  再往 0 降就沒有差別了。
- 驗證和測試時仍用原本的式 11，不用退火。

模型設定（附錄 §3）：

| 項目 | 值 |
|---|---|
| 編碼器 | LSTM，512 個單元 |
| 解碼器 | HyperLSTM，2048 個單元 |
| M（混合數） | 20 |
| N_z（描述卡長度） | 128 |
| 其他 | Layer Normalization；遞迴 dropout，保留 90% |
| 訓練 | batch 100、Adam、學習率 0.0001、梯度裁剪 1.0 |
| 資料增強 | Δx、Δy 各乘一個獨立的 U(0.90, 1.10) 亂數 |
| 預設 | w_KL = 1.00、KL_min = 0.20、R = 0.99999 |
| 參數量 | **論文沒寫** |

## 5. 實驗與數字

**表 1（§4）**：測試集損失。L_R 越低越好；它是連續分布的 log 機率密度，所以可以是負數。

| 資料集 | w_KL = 1.00 的 L_R / L_KL | w_KL = 0.25 的 L_R / L_KL | 只有解碼器的 L_R |
|---|---|---|---|
| cat | −0.98 / 0.29 | −1.46 / 1.01 | −0.57 |
| pig | −1.14 / 0.22 | −1.52 / 0.80 | −0.82 |
| cat, pig | −1.02 / 0.22 | −1.50 / 0.98 | −0.75 |
| crab, face, pig, rabbit | −0.91 / 0.22 | −1.47 / 1.17 | −0.67 |
| mosquito | −0.67 / 0.30 | −1.41 / 1.54 | −0.34 |
| garden | −0.79 / 0.20 | −0.99 / 0.54 | −0.62 |

（表 1 另有 face、firetruck、owl、yoga 四列，趨勢相同；w_KL = 0.50 那欄也介於兩者之間。）

讀法：
- w_KL 越小，L_R 越低、L_KL 越高，兩者互相拉扯。
- **有描述卡的版本永遠比只有解碼器的版本低**。作者說：解碼器事先不知道整張圖長什麼樣，所以它的 L_R 是有條件模型的上界。

其他結果**全部是看圖、沒有數字**：
- §4.1 重建：三隻眼的貓被畫回兩隻眼；牙刷餵給貓模型，畫出有貓耳朵和鬍鬚的牙刷形狀。
- §4.2 內插（interpolation）：w_KL 越高，貓和豬之間的過渡圖越連貫（圖 6 左）。
- §4.3 類比：全豬 − 豬頭 + 貓頭 = 全貓（圖 6 右）。
- §4.4 接著畫：只用解碼器、τ = 0.8，替畫一半的圖畫出好幾種結尾（圖 7）。
- 附錄 §4：75 類合起來訓練的無條件模型畫出來亂七八糟；4 類模型通常畫單一類，偶爾混在一起（附錄圖 4）。
- 附錄 §6：w_KL = 1.00 的模型，L_R 比較高，重建卻比較連貫。

**論文沒有的東西**：沒有「畫得像不像」的量化指標、沒有拿分類器去辨識生成的圖、沒有人類評分、沒有檢查是不是抄訓練資料。

## 6. 作者自己承認的限制（附錄 §4、§6）

1. **長度**：大約 300 個點以上就很難訓練，所以資料先簡化到 200 點以內。
2. **複雜的類別**（mermaid、lobster、frog）會畫出平滑的圓弧，像很多張圖的**平均**，不像某個人畫的一張。作者類比成 VAE 生成像素圖時的模糊。
3. **很多類別一起訓練會失敗**：75 類模型的每張圖都混了好幾類的特徵。作者提出的解法是「把類別資訊放在潛在空間外面」，但留到未來才做。
4. **L_R 低 ≠ 圖比較好**：舉例來說，一張臉的大部分點都在畫外框，眼睛嘴巴只佔少數點。模型可以把外框畫得很準、五官畫得亂七八糟，L_R 反而比較低。

我另外注意到的：「補長到 N_max」這個停筆方法沒有對照數字；所有品質判斷都靠看圖。

## 7. ⭐ 對 Sell Anything 有什麼幫助

### 7.1 畫圖 GPT（F3／F4）：主要對象

| 觀念 | 對應 design-v2 | 現況 | 要做什麼 | 代價 |
|---|---|---|---|---|
| stroke-5 是我們 token 序列的原型：(Δx, Δy) → K-means 動作 token；p2 → `[lift]`；p3 → `[end]` | §5.1 | 已是這樣設計 | 不變 | — |
| 只有解碼器的接著畫模型（§3.3） | §5.2 | decoder-only 加類別 token | 不變 | — |
| **多類別一起訓練會混類**（附錄 §4） | §5.2 引用了 | 設計用類別 token 解決 | ⚠️ 見下方「風險」 | — |
| 選 checkpoint 和 τ 看辨識率、不看 loss（附錄 §6） | §5.2、§5.5 | 已採用 | 補上原因：小道具在一張圖裡只佔少數點，loss 量不到它畫得像不像 | — |
| Δx、Δy 乘 U(0.9, 1.1)（附錄 §3） | §5.2 | 已採用 | 不變 | — |
| 溫度 τ | §5.2 寫「Sketch-RNN used 0.2–0.9」 | **只對圖 3 正確** | 論文整體用了 0.01–1.0（圖 5 從 0.01 起跳；附錄圖 6 全用 τ = 0.1）；§5 建議用「高 w_KL + 低 τ」畫出比較工整的版本。建議 sweep 加上 0.1 | 只多取樣，幾分鐘 |
| 停筆是 "a key challenge"，但論文沒有數字 | §5.2「每個序列都以 `[end]` 結尾」 | 我們用 `[end]` token，不補 p3 | 在 §5.5 加一項**停筆檢查**：生成長度 vs 真實長度（每類中位數比、沒在 context 內結束的比例、太早結束的比例） | CPU，不用多訓練 |
| 長度上限 | §5.2「context 取第 99 百分位」 | Transformer 沒有 RNN 的 300 點難題 | 實測貓：點數中位數 58、第 90 百分位 84、第 99 百分位 119、最長 475；超過 200 點的只有 0.077%。粗估 token 數（點 + 每筆一個 lift + 3）的第 99 百分位約 141。最後以 345 類全部重算為準 | — |
| 複雜類別會畫成平均的圓弧 | §5.5、§13.4「畫完再驗證」 | 已有 | 場景道具裡 castle、house 這種複雜的，驗證失敗率可能偏高，先列入觀察 | — |

**⚠️ 這篇提高了一個風險**：Sketch-RNN 展示的成功例子幾乎都是**一類一個模型**（最多 4 類）。
75 類合訓失敗了；「加類別資訊」只是作者提出的未來方向，**這篇沒有證明它有效**。
我們打算用**一個**模型、靠類別 token 畫 **345** 類，每類只有 15,500 張（論文每類 70K）。
→ 建議先在少數類別上做小規模試驗，量到辨識率再擴到 345 類（見「建議改動」）。
A2 Sketchformer 是一個 345 類的 Transformer，讀完再回頭評估這個風險。

**不該照搬的**：
- **VAE 那一半（編碼器和 z）**：我們三種模式都不需要「把一張現有的圖編成卡片」，不用做。
- **GMM 輸出**：我們用 Sketchformer 的 1,000 個標準動作加 softmax，一次分類就決定下一步，比較好訓練、也好取樣。
- **把位移正規化成標準差 1**：K-means 字典直接在像素位移上分群，不需要。
- **補長到 N_max 並把 p3 算進損失**：那是 RNN 加三選一筆狀態的解法。我們的 `[end]` 就是普通 token；`[pad]` 要不要算進損失，留到實作時決定。
- **HyperLSTM、2048 個單元**：論文沒給參數量，無法拿來估我們的模型大小。

### 7.2 「畫到一半」辨識模型（F1）

§4.4 證明了畫一半的筆畫裡，已經有足夠資訊讓模型畫出好幾種合理結尾。
這是一條替代路線：先替玩家把圖畫完，再拿完整的圖去辨識。
**不建議**：每次抬筆都要生成整段再分類，延遲加倍，錯誤也會累積。現在的計畫（從筆畫 Transformer 微調，DeepSketch 2 的做法）比較直接。

### 7.3 筆畫 Transformer、CNN（F2）

只有背景知識：我們筆畫 Transformer 的每點輸入 (x, y, dx, dy, 抬筆, 下筆)，就是 stroke-5 再加上絕對位置。
資料的 RDP ε = 2 也和論文相同。不用改。

### 7.4 買家 GPT

只有一般觀念：
- 溫度一樣適用在買家說話的取樣上。
- 「loss 低 ≠ 輸出好」也一樣成立。design §6.7 已經改用任務指標（on-topic、Δ 準確率、copy rate）評估。

### 7.5 對論文方向 A／B

- **方向 A**：
  - 它已經做掉了：一筆一筆生成線條圖、接著畫、潛在空間內插。我們**不能宣稱**「一筆一筆生成線條圖」是新的（related-work §6 第 5 點已經這樣寫）。
  - 它留下的空白：沒有量化畫質、沒有辨識率、沒有人類實驗、**沒有多物件場景**（一次只畫一個東西）、沒有拿圖當**解釋**。
    我們的 (a)「場景當 NPC 估價的解釋」、(b)「筆畫塗鴉當解釋媒介」、(c)「同一組標籤驅動估價、對話、場景」，這篇都沒碰到。
- **方向 B**：幾乎無關。唯一勉強相關的是表 1：多給模型一張描述卡，L_R 就下降（貓 −0.57 → −0.98）。
  這和「給小模型多少結構化資訊」是同一類問題，但這篇量的是重建，不是推廣到沒看過的類別。

### 7.6 有沒有推翻之前的決定？

**沒有推翻任何一條 D1–D19 或 design-v2 的決定。** 有兩件要修正或補強：

2. 「一個模型加類別 token 畫 345 類」在這篇裡是**未驗證的提議**，不是證據。design 不該把它寫成 Sketch-RNN 證明的事。

   (b) 第 13 點和第 14 點之間會畫出線嗎？為什麼？

   (b) 鐘形 σ = 8 px、τ = 0.25 時，σ 變成多少？
   (c) 用一句話說：為什麼畫場景道具時，可能想用比較低的 τ？
3. 表 1 裡，貓的「只有解碼器」L_R 是 −0.57，w_KL = 0.25 的有條件模型是 −1.46，後者低很多。
   (a) 附錄 §6 為什麼說 L_R 低不代表圖畫得好？用臉的例子講。
   (b) 這件事對我們「畫圖 GPT 要選哪個 checkpoint」有什麼影響？
   (c) Sketch-RNN 的 75 類模型失敗了。我們的對策是什麼？這篇論文有沒有證明那個對策有效？

1. (a) (76 − 231, 103 − 141) = (−155, −38)。(b) 不會。第 13 點的 p2 = 1 表示畫完這點就抬筆，下一段是筆在空中移動。

2. (a) τ = 1：e² / (e² + e + e) = 7.389 / 12.826 ≈ 0.576；τ = 0.5：分數變 (4, 2, 2)，54.60 / (54.60 + 7.39 + 7.39) ≈ 0.787。

3. (a) 臉的大部分點在畫外框，五官的點很少；外框畫得很準就能拿到低 L_R，即使五官亂掉。
   (b) 不能用驗證集 loss 選，要用分類器辨識率選（design §5.5）。
   (c) 每個序列開頭放類別 token。論文沒有證明，只把「類別資訊放在潛在空間外」列為未來工作。
