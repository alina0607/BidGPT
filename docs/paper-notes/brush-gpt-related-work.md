## 1. R1 Collaborative Neural Painting（CNP）

### 一句話
讓人和 AI 一起畫：使用者畫幾筆（或只說「我要一隻貓」），AI 把剩下的筆畫補完，而且**不需要參考照片**。

### 日常類比
像兩個人輪流畫同一張畫：你先畫個大概的輪廓，朋友幫你加細節；或你擦掉一塊，朋友幫你補回去。
朋友手上沒有照片可以照著畫，只知道「這是一隻貓」。

### 做法（照論文章節）
- **任務（§4）**：一幅畫 = 400 筆，每筆 8 個數字（x、y、寬、高、角度、R、G、B），分 4 層由粗到細（用 Stylized Neural Painting 把圖切成 m×m 的格子，每格 12 筆，m 從 1 到 4）。
  模型 G 吃兩種條件：類別 c 和使用者已畫的筆 s_ctx，輸出補完的筆。
- **模型（§5.2）**：Masked Diffusion Transformer。把「要補的筆」加上雜訊，transformer 一次把整串的雜訊預測出來（DDPM、1,000 步，示範時用 70 步）。
  已畫的筆不加雜訊，當作條件。類別用 adaLN-Zero 注入（跟 DiT 一樣）。
- **Interaction-aware Masking（§5.1）**：訓練時模擬五種使用情境來決定遮哪些筆：只給粗層（Level）、隨機、一個方塊（Square）、最後連續幾筆（Block）、全部遮掉只給類別（No context）。
- **Position-aware Attention Bias（§5.3）**：在注意力上加一項「兩筆在畫面上越近，越要互相注意」，權重隨雜訊大小調整（雜訊越大越不信位置）。
- **Multiple Conditions CFG（§5.4）**：同時對「已畫的筆」和「類別」做 classifier-free guidance，兩個 guidance 都設 1.5（§7.1）。

### 數字（全部取自論文）
| 項目 | 數字 | 出處 |
|---|---|---|
| 資料 | 10 類動物（cat、dog、eagle、elephant、lion、parrot、rabbit、squirrel、tiger、wolf），每類 ≥10K 張、留 500 張測試，共 101,052 串 | §6.1 |
| 只給類別、從零畫（No ctx）的 FID | **30.12** | 表 2 |
| 離散 token 的基準線（每個參數切成 256 格，BERT / MaskGIT 式遮罩填空）No ctx FID | **320.43 / 336.18** | 表 2 |
| 連續數字、MSE 的 transformer No ctx FID | 443.86（收斂成每類的「平均圖」） | 表 2、§7.2 |
| 消融：不用 Interaction-aware Masking 的 No ctx FID | 233.21 → 用了 36.96 | 表 4 |
| 模型越大越好：S / B / L 的無條件 FID | 55.25 / 36.29 / 30.12 | 表 6 |
| 使用者研究（20 人、894 票）：第一名 | 真畫 81%、他們的模型 17% | 表 3 |
| 速度 | A100 上 1,000 步約 8 秒；70 步約 0.56 秒 | §7.5、表 7 |

### 作者承認的限制（§8）
資料集要再擴大；想加語言模型做開放類別；取樣要更快；生成的物體跟背景怎麼融合還沒處理。

### ⭐ 跟我們的差別
1. **最重要的一條：他們說「離散 token」失敗了，但他們試的是「遮罩填空」，不是我們的「自迴歸」。**
   他們把每個參數獨立切成 256 格 token（一串 L×8 個 token），用 BERT / MaskGIT 的方式訓練，無條件 FID 320–336（表 2）。
   他們的解釋是「每個參數各自變成一個 token，讓模型很難算出筆與筆之間的關係」（§7.2）。
   我們也是每個欄位一個 token（一串 3,063 個），但用的是**一個接一個猜的自迴歸**，加上**每個欄位只在自己的 token 範圍裡選**，256 張樣本全部能換算回圖（devlog 2026-10-11 §7），I 的眼睛分數到真畫的 0.91（devlog 2026-10-12 §5）。
   → 這不是同一個實驗，所以**不能說我們推翻了他們**。IconShop（R11）在向量圖示上也看到 BERT 式遠差於自迴歸（FID 43.61 vs 6.08），所以 R1 的失敗比較可能出在「遮罩填空」，不在「離散 token」。
2. **資料來源**：他們用 Stable Diffusion 生成的假照片，我們用真照片加上人工標的臉部點。
3. **評估**：他們只看整張圖的 FID 和 L2；**沒有任何一個指標在量「眼睛、臉的結構對不對」**。
4. **筆順**：他們評分時用匈牙利配對把同層的順序抹掉，等於假設順序不重要；我們量到順序非常重要（亂序時「下一筆的 x」loss 5.53，跟亂猜的 ln 256 = 5.55 一樣，devlog 2026-10-11）。
5. **規模**：他們的模型要 4 張 GPU；我們一台筆電。

### 可以學的
- **Level 任務 = 「給你真畫的前幾層，你畫剩下的」**。我們可以不用訓練就做：把真畫的第 1（或 1–2、1–3）階段餵給 J，讓它畫剩下的，再用眼睛評審量。
  這能直接回答「眼睛是在粗、中、細哪一層出錯」（我們目前只量過真畫被切斷時的分數 0.429 / 0.495 / 0.527 / 0.537）。
- **他們的資料集公開了，而且有狗。** 如果之後要做狗，或要跟別人直接比數字，可以用同一份資料、同一套評估。
- **評估方式**：FID 對**留出的測試畫**算（不是對自己的訓練畫），加上匈牙利配對的筆畫 L1、使用者排名研究。這些是教授會期待看到的標準做法。
- **CFG 拿掉條件的訓練方式**跟我們的 P5 想法一樣，他們用 1.5 有效。

## 2. R2 AttentionPainter

### 一句話
「照著一張照片，用筆畫把它畫出來」，但**一次就把 256 筆全部算出來**，比一筆一筆來快很多；另外附一個在筆畫參數上做的擴散模型，可以憑空生成。

### 日常類比
傳統方法像畫家看一眼照片畫一筆、再看一眼畫一筆；AttentionPainter 像一台印表機，看一眼就把 256 筆同時印上去。

### 做法（照論文章節）
- **一次預測大量筆畫（§4.2）**：ViT-small 抽照片特徵，再用 1 個交叉注意力 + 4 個自注意力區塊，把 256 個「筆畫查詢」變成 256 筆的參數。
- **Fast Stroke Stacking（§4.3）**：疊筆時每個像素只算最上面 k 筆（k ≤ 10），因為底下的筆被蓋住、對結果和梯度幾乎沒影響。訓練快 13 倍（表 5：每步 6.42 秒 → 0.48 秒）。
- **Stroke-density Loss（§4.4）**：用 Sobel 邊緣算出「細節多的地方」，懲罰在那裡用大筆，逼模型在細節處用小筆。作者特別說它讓**動物的眼睛和條紋**畫得出來（§6.3.3、圖 8；套在 SNP 上也有效，§6.5、圖 9）。
- **Stroke Diffusion Model（§5）**：在筆畫參數上做擴散（8 個交叉注意力 + 8 個自注意力、寬 512、1,000 步），可以無條件生成，也可以補洞、照草圖改圖。

### 數字
| 項目 | 數字 | 出處 |
|---|---|---|
| 照片重建（CelebAMask-HQ，1,000 筆）L2 / SSIM / LPIPS | 0.0024 / 0.7069 / 0.0941（全部方法裡最好） | 表 2 |
| 每張圖推論時間 | 0.08 秒（SNP 約 500 秒） | 表 3 |
| 使用者研究（40 人）：平均排名、拿第一的比例 | 1.39、77.91% | 表 8 |
| 生成模型的訓練 | 1 張 RTX 4090，約 2 天 | §6.1 |
| **無條件生成的品質** | **沒有任何數字**，只有補充圖 4（250 筆人臉） | 補充 §6 |

### 跟我們的差別
- 它的重點是**重建照片**，生成只是展示。我們的重點正好是生成。
- 它的筆是**一整組同時出來**，沒有「先畫什麼、後畫什麼」的過程；我們每一筆都看得到前面所有的筆。
- 它的無條件生成**沒有被量化**；我們有眼睛評審、FID、抄襲檢查。

### 可以學的
- **Stroke-density Loss 可以用在我們的「畫家」**（catbrush，產生訓練資料的那一步），讓訓練畫裡的眼睛細節更多。
  但這會改變訓練資料，等於要把一萬多隻貓重畫，代價很高；而且我們量過真畫的眼睛分數（0.537）已經不低，問題主要在模型生成，不在資料。**先記著，不建議現在做。**
- 他們的使用者研究問卷三個面向（像不像、細節、看起來像不像人畫的）可以借來設計我們的人類評估。

## 3. R3 PaintCopilot

### 一句話
一個給藝術家用的繪圖 App：AI 看著你目前畫到哪，**一筆一筆接著畫**，你隨時可以打斷、改掉。

### 日常類比
像旁邊坐了一位助手：你畫到一半把筆交給他，他看看畫布、猜你想畫成什麼樣子，接著畫幾筆；你覺得不對就把筆拿回來。

### 做法（照論文章節）
- **三個模型（§6.3）**：
  - **目標預測器**：小型 ViT，在 Stable Diffusion 的 VAE 潛在空間裡，從「目前的畫布」直接猜「畫完會長怎樣」。
  - **筆畫預測器**：因果 transformer，看最近 **50 筆**加上畫布的壓縮向量（AdaLN 注入），用 **flow matching** 產生下一筆的 8 個連續數字。作者特別說他們選連續數字、**不用離散 token**（§6.3.3）。
  - **區域取樣器**：條件 VAE，在使用者圈起來的區域裡、照語意標籤（例如「左眼」）生出一串筆。
- **接著畫的每一筆，還會被最佳化去貼近目標圖**（§6.1「Stroke Completion」）。所以它不是純粹由模型自己發明，而是「模型提議 + 拉向目標圖」。
- **資料（§6.3.1）**：3,000 張古典人像畫，每張用筆畫渲染產生 300–400 筆，**順序用語意分割決定**（15 個標籤由粗到細：背景、頭髮、衣服 → 臉 → 眼、鼻、嘴），再參考表面法線（平坦的先畫、大筆）和 DINO 注意力（顯眼的地方多下筆）。

### 數字
| 項目 | 數字 | 出處 |
|---|---|---|
| 目標預測器：空白畫布時 LPIPS / PSNR | 0.89 / 4.88 dB | §7.1、圖 10a |
| 畫了 11% 的筆之後 | 0.48 / 17.40 dB | §7.1 |
| 筆畫預測器：平均 L1（全部欄位） | 0.100；顏色最難、大小最容易 | §7.1、圖 10b |
| 區域取樣器重建 L1 | 0.179 | §7.1 |
| 10 位藝術家、兩週：控制感 / 擁有感 / 貢獻 / 方向一致（7 分量表） | 4.40 / 4.30 / 3.50 / 3.80 | §8.2、圖 13 |
| 訓練 | 8 張 RTX Pro 6000 | §6.3.5 |

### 作者承認的限制（§10）
只做人像；訓練用的筆畫順序是程式產生的，不是真人畫的；技術評估只檢查行為，不代表「畫得好」；10 個人、沒有對照組。

### 跟我們的差別
- 它**不是從零發明**：需要畫布，而且每筆會被拉向目標圖。我們完全不看任何圖。
- 它只看**最近 50 筆**；我們看全部 3,063 個 token（所有之前的筆）。
- 它是 HCI（人機互動）論文，重點在藝術家的使用經驗；我們的重點是模型自己能不能畫出結構正確的動物。
- **但它在筆順上的想法跟我們很接近**：它刻意設計「先大區塊、最後才畫眼睛」這種**語意順序**；我們是「空間順序」（由上往下的帶狀）。

### 可以學的
- **語意順序**：把眼睛的筆集中在一起、放在階段的最後畫。這正是我們 devlog 2026-10-12 §1 的第 (2) 點（「每隻眼睛是自己的一步」），當時結論是「要重畫才做得到」，因為重疊的筆必須保持先後。
  PaintCopilot 的做法是**在產生資料時就照語意順序畫**，等於證明這條路可行，但我們要重畫。
- **讓模型「看見」畫布**：它把渲染出來的畫布壓縮後餵給模型。我們的模型只能從 token 歷史「想像」畫布長什麼樣。
  在每個階段開頭餵一次目前畫布的影像特徵，可能幫助眼睛定位。這是架構改動，要另外訓練。
- **目標預測器的曲線**（畫越多、越猜得到最後長怎樣）可以借來分析我們的模型：畫到第幾筆時，貓的樣子就「定了」？

## 4. 第二、三輪：另外十篇（R4–R13）

### R4 StrokeNUWA（ICML 2024）：文字 → 黑白向量圖示
- **做什麼**：把 SVG 的路徑指令（M、L、C 三種，每條 9 個數字）用殘差 VQ 壓成「筆畫 token」（碼本 4,096，長度壓到原本的 6.9%），再用 30 億參數的 Flan-T5 從文字生成這些 token（§3、§4.1）。
- **資料與算力**：FIGR-8-SVG 黑白圖示，訓練 740K 張；64 張 V100（§4.1）。
- **數字**：FID 6.513、CLIPScore 17.994，生成一張約 19 秒（表 2）。生成後還要一個「SVG Fixer」把斷掉的路徑接起來（§3.2.3）。
- **跟我們的差別**：線條圖示，**沒有顏色、筆刷、疊色**；要給文字；token 是 VQ 學出來的碼，不是可讀的欄位。
- ⚠️ **最重要的一點**：它比較的 **IconShop**（Wu 等，ToG 2023）是「把 SVG 座標切成離散 token、自迴歸生成向量圖示」。所以「**離散 token + 自迴歸**」這個表示方式本身**在向量圖示領域已經有人做過**。我們不能宣稱這個組合是新的，只能說「用在**有顏色、會疊色的油畫筆觸**、由粗到細」上。IconShop 的全文見 R11。

### R5 ProcessPainter（2024）：文字 → 8 格繪畫過程影片
- **做什麼**：Stable Diffusion + AnimateDiff 的時間注意力，生成 8 張 512×512 的影格，代表從空白到完成（§3.2）。先在 30,000 段**程式產生**的過程上預訓練（用 Learning to Paint、SNP、Paint Transformer 畫 DiffusionDB 的圖），再用 3 位畫家的 95 段真實過程做 LoRA（§3.3）。
- **數字**：照片 → 過程的最後一格重建 MSE 0.014820（表 1）；44 人選「比較像人畫的」78–85%（表 2）。
- **跟我們的差別**：輸出是**像素影格，不是筆畫參數**；只有 8 格，不是幾百筆；要給文字。它自稱「第一個從文字生成繪畫過程」（§4.4）。

### R6 Generating Past and Future（PaintsAlter，ToG 2025）
- **做什麼**：使用者上傳一張畫布，用影片擴散模型（LTXVideo、CogVideoX）生成**之前或之後**的畫布狀態（§3）。
- **資料與算力**：19 位畫家 2018–2020 年的真實錄影，切成 20k 段；8 張 H100，訓練 4–9 天（§3.4）。
- **數字**：留出的 5% 上 PSNR 17.04、SSIM 0.6712、LPIPS 0.4022（表 1）；13 人使用者研究（表 2）。
- **跟我們的差別**：**像素**；必須先有一張畫布；作者自己說從真實照片重建過程是「本質上不適定的問題」（§4.7）。

### R7 Inverse Painting（SIGGRAPH Asia 2024）
- **做什麼**：給一張**完成的畫**，倒推縮時影片。每一步先用 LLaVA 說「下一步畫什麼」（例如「天空」），再產生區域遮罩，最後用擴散模型更新畫布（§3）。
- **資料**：294 段壓克力風景畫影片（§4）。
- **數字**：LPIPS 0.364、FID 150.6（表 1）；33 人評分是第二名 SVD 的 1.9 倍。
- **跟我們的差別**：需要目標畫；像素；只學風景（人像會失敗，§5）。
- **值得記的**：它把「由遠到近、一次畫一個語意區域」的**順序**當成模型要學的東西，並發現生成的「時間圖」很像深度圖（圖 10）。

### R8 Loomis Painter（2025-11）
- **做什麼**：用 140 億參數的 Wan 2.1 影片模型，給一張圖、生成繪畫過程影片，還能換媒材（油畫、鉛筆、Loomis 人頭畫法）（§3）。
- **資料與算力**：737 支 YouTube 教學影片（表 1）；4 張 H100 訓練 24 小時（§5）。
- **⭐ 跟我們方向 A 有關的發現**：**把影格順序倒過來訓練，比照真實順序好**：FID 172.62 → 164.29、LPIPS 0.42 → 0.39（表 2）。作者的解釋是影片模型的條件圖放在第一格，倒過來才對得上（§3.3）。也就是說：**順序會影響可學性**，雖然它的理由跟我們不同。
- **跟我們的差別**：像素；需要目標圖。

### R9 Birth of a Painting（2025-11）
- **做什麼**：給一張畫，用可微分渲染**最佳化**出貝茲曲線筆畫，再加 StyleGAN 筆刷質感和可微分「抹色」（§3）。
- **跟我們的差別**：跟我們的**畫家**（catbrush，產生訓練資料的那一步）是同一類：重建，不是生成新的畫。
- **可以學的**：抹色讓色彩過渡更像真的油畫。如果之後要讓訓練畫更像油畫，可以參考；但那要重畫全部資料。

### R10 StrokeDiff（2026-03）
- **做什麼**：只用一位畫家掃描的 **470 筆**真實筆觸，訓練擴散模型生成**單一筆觸的外觀**（質感、形狀），再接到 Paint Transformer 式的流程去**重建一張給定的圖**（§3.4）。
- **⭐ 跟順序有關**：它加了一個「排序損失」讓筆有正確的先後；不加的話，一組同時預測的筆會「完全沒有順序」、疊錯（§4.5.2、圖 5、圖 12）。
- **跟我們的差別**：生成的是**一筆的樣子**，不是一整幅新的畫；需要目標圖。

### R11 IconShop（SIGGRAPH Asia 2023）：離散 token 自迴歸生成向量圖示
- **做什麼**：把 SVG 的 M / L / C 指令和座標轉成 token（座標用 `x×w+y` 變成一個 1D token，100×100 格；詞彙 10,007），用 12 層的解碼器 transformer 一個接一個猜（§3.2、§3.4）。訓練時 10% 不給文字，所以**也能無條件生成**（§3.5、§4.1）。
- **資料**：FIGR-8-SVG 黑白圖示，用了 30 萬張（§4.1）。
- **⭐ 數字**：無條件生成 FID **6.08**；同一份資料用 BERT 式遮罩填空 **43.61**；DeepSVG+GAN 11.95（表 2a）。作者說 BERT 會在好幾個位置同時猜出「結束」，所以常常提早斷掉（§4.2）。
- **作者承認的限制**：只能做黑白圖示（§6）。
- **對我們的意義**：
  1. 「離散 token + 自迴歸 + 無條件」**在向量圖示上已經有人做到，而且做得很好**。我們不能宣稱這個組合是新的。
  2. 但它也**幫我們解釋了 R1 的結果**：R1 的離散 token 基準線是 BERT / MaskGIT 式（FID 320–336），IconShop 在自己的資料上也看到 BERT 式遠差於自迴歸。所以「離散 token 不行」比較可能是「遮罩填空不行」。這是別人的實驗，不是我們的，**要在論文裡引用，不能當成我們的發現**。
  3. 跟我們的差別：沒有顏色、沒有疊色、沒有筆刷大小，順序就是 SVG 檔案原本的路徑順序，沒有設計過。

### R12 Intelli-Paint（ECCV 2022）：讓畫的順序比較像人
- **做什麼**：強化學習代理人**照著一張目標照片畫**，刻意設計成「先畫背景、再一個一個加前景物體」（用顯著性圖分層）、「注意力窗由粗到細移動」、「相鄰兩筆位置和顏色不要跳太遠」，最後再把多餘的筆刪掉（§4）。
- **數字**：約 300 筆時 CUB 鳥的像素誤差 50.94，比 Paint Transformer 的 82.43 低（表 1）；Mechanical Turk 50 人，在 69–91% 的比較裡選它比較像人畫（表 1 右）。
- **作者承認的限制**：只模仿幾個常見習慣，不是真的像人；依賴預訓練的顯著性模型；要在真照片上訓練（§6.3）。
- **對我們的意義**：它的順序是為了「**讓人看得懂**」設計的，用人類研究評估；**沒有**拿不同順序去比較「模型學不學得會」，也不是生成新的畫。

### R13 Interactive Neural Painting（I-Paint，CVIU 2023）：R1 的前身
- **做什麼**：給參考照片、目前畫布、最近 8 筆，條件 transformer VAE 提議接下來 8 筆（§3）。
- **資料**：ADE20K 戶外 5,000 張、**Oxford-IIIT Pet 7,349 張貓狗照片**，用 SNP 拆成筆畫（§4.1）。
- **⭐ 最接近我們的一點**：它在做資料時**重新排了筆順**：讓相鄰兩筆的位置、顏色、大小差越小越好、而且盡量不要跳到別的物體上，**同時保證重疊的筆維持原本的先後**（所以畫面不變），用 TSP 類的「循序排序問題」解法（LKH）求解（§4.1 式 7）。這跟我們「保持重疊、其餘重排」的想法**幾乎一樣**，只是它的目標是「連續」，我們是「由上往下的帶狀」。
- **但**：它重排是為了讓順序像人，**沒有量重排前後模型學得好不好，也沒有比較不同排法**。
- **數字**：在貓狗資料上 Fréchet Stroke Distance 1.12（PT 11.3、SNP 16.3，表 3）；8 人 960 票，95–98% 選它（表 4）。

## 5. 讀完十三篇之後，我們有、它們都沒有的（修正版）

先講**要改口的**：
- ❌「離散 token + 自迴歸」**不能**再單獨當成新點：IconShop（R11）已經用這個方式**無條件**生成向量圖示，而且證明它比 BERT 式好很多。
- ❌「保持重疊的先後、其餘重新排列」這個**做法**也不是我們先想到的：I-Paint（R13）2023 年就這樣處理資料。
- ❌「從零生成筆畫」**也不能**單獨當新點：R1（只給類別）和 R2 的 SDM（無條件）都做了。

**還站得住的（目前十三篇裡沒有任何一篇同時做到）**：
1. **完全無條件（不給類別、照片、畫布、文字），自迴歸地一筆一筆畫出一整幅有顏色、會疊色、由粗到細的油畫式動物**。最接近的是 R1（要給類別、擴散、資料是 Stable Diffusion 生成的假照片）、R2 SDM（擴散、只放圖、人臉/鳥/車）和 R11（自迴歸、無條件，但是黑白線條圖示）。**這一點要講精確**：新的不是「自迴歸」也不是「無條件」，而是把它用在有顏色、會互相覆蓋、有粗細階段的油畫筆觸上。
2. **用一個獨立模型量「部位畫對了沒」**（眼睛評審）。十篇用的都是整張圖的指標（FID、LPIPS、SSIM、CLIP、DINO、PDP）或人類研究，**沒有人量結構**。
3. **系統地比較筆順對可學性的影響**。十三篇裡有六篇碰到順序：R1 用匈牙利配對忽略它；R3、R7、R12 設計了「像人」的順序；R13 用「保持重疊、讓相鄰筆接近」重排資料；R8 發現影格倒序比較好；R10 加排序損失。**但沒有一篇在同一份資料、同一個模型上比較好幾種順序對學習的影響**，R12、R13 的順序都是用「像不像人」來評估。我們已有兩個證據（亂序時 x 的 loss 5.53 ≈ ln 256；轉正後重排讓 I 在 CAT 驗證貓上 3.9491 → 3.9407）。
4. **先寫一個很小的構圖計畫（9 個臉部點）再畫**，並量過效果（眼睛比 D 0.84 → E 0.87，I 0.91）。R7 用 LLaVA 決定下一步畫什麼、R3 用目標預測器，都是另外的大模型；我們是同一個小模型自己先寫。
5. **真照片 + 人工標的臉部點**當資料，一台筆電就訓練得起來。這兩點只能當附帶優點。

⚠️ 還沒讀全文的相關論文：Stroke-GAN Painter、MambaPainter、AnimatePainter、Compositional Neural Painter、Semantic Guidance + RL。從 R1–R13 的引用看，它們都是「照著照片畫」的方法，對第 1 點威脅小；第 3 點（順序）如果要寫成論文主軸，送出前還要再做一次有系統的文獻搜尋（例如搜尋 stroke ordering、sequence order learnability、autoregressive order 在其他領域的研究）。

## 6. 可以做的獨特研究（依我目前的判斷排序）

### 方向 A ⭐「筆畫應該用什麼順序，模型才學得會？」
- **問題**：同樣的一幅畫（同一組筆），換不同的順序排，自迴歸模型的學習難度、生成品質差多少？
- **為什麼新**：R1 把順序當雜訊忽略；R3、R7、R12 用「像人」的順序但沒比較；R13 已經用「保持重疊、讓相鄰筆接近」重排資料，但只用來讓順序像人；R8 發現影格倒序比較好、R10 證明沒有順序會疊錯，但**都沒有在同一份資料上比較多種順序對學習的影響**；我們已經有兩個證據（亂序時 x 學不會；轉正後重排連 I 的 loss 都變好）。
- **比較的順序要包含 R13 的那一種**（連續性：位置、顏色、大小接近，用 LKH 求解），這樣才是跟最接近的前人做法正面比較。
- **實驗**：同一份資料、同一個模型，只換順序：畫家原本的隨機順序 / 保持重疊的帶狀順序（現在的）/ 語意順序（眼睛最後）/ 粗到細的格子順序（SNP、R1 的做法）。每個訓練一次，比眼睛分數、FID、各欄位 loss。
- **代價**：每種順序一次訓練（Mac 上約一天、A100 約 1 美元）；語意順序要先解決「重疊的筆不能換先後」的限制。

### 方向 B ⭐「從粗到細的生成，錯誤出在哪一層？」
- **問題**：生成的畫眼睛不好，是粗的構圖就錯了，還是細節沒畫好？
- **做法**：借 R1 的 Level 任務。給 J 真畫的前 k 個階段（k = 0、1、2、3），讓它畫剩下的，用眼睛評審量。跟「真畫切在第 k 階段」的分數比。
- **為什麼新**：三篇都沒有在「部位」層級量錯誤出在哪；我們已經有真畫逐階段的分數可以當上限。
- **代價**：**不用訓練**，只要取樣和評審（Mac 上幾小時）。⭐ 最便宜、最先可以做。

### 方向 C「先寫構圖計畫，再畫」
- **問題**：讓模型先輸出一個小小的計畫（臉部點），再照著畫，能不能讓結構（眼睛）更對？計畫加上 guidance（P5）呢？
- **證據**：E 0.87、G 0.90、I 0.91（devlog 2026-10-12）。
- **為什麼新**：R3 用一個獨立的大模型猜目標圖；我們讓**同一個模型自己先寫計畫**，而且計畫非常小（18 個 token）。
- **代價**：P5 要改程式加一次訓練。

### 方向 D「離散 token + 自迴歸 vs 擴散，在同一個資料上公平比較」
- **問題**：R1 說離散 token 不行；那是遮罩填空的問題，還是離散 token 本身的問題？
- **做法**：用 R1 公開的資料集（10 類動物、含狗），把我們的模型（加類別 token）訓練在上面，用 R1 的評估方式算 FID，直接跟表 2 比。
- **代價**：最高。資料要重新 token 化（他們的參數是寬高 + RGB，沒有透明度）；10 萬串資料在 Mac 上訓練會很久，可能要租 GPU（要你同意）。
- **風險**：可能輸給他們的擴散模型；但「輸多少、為什麼」本身也是結果。這也剛好是之後做狗的路。

### 不建議當主題的
- 「一台筆電就訓練得起來」只能當附帶優點，不夠撐起一篇論文。
- 「真照片 vs 生成的假照片」差異太多變因，很難做乾淨。

### 8.3 別人也做了、但我們做得比較嚴謹的（⚠️ 不是品質更好，是證據更完整）
沒有任何一項是同資料同指標的正面比較，所以**只能說「做得比較嚴謹」，不能說「比較好」**。
- **抄襲檢查有對照組**：R11 用 CLIP 相似度門檻 0.98 判斷「一樣」。我們拿生成畫到訓練畫（含鏡像）的最近距離，**跟沒看過的驗證畫比**：run I 生成畫中位數 0.1386、驗證畫 0.1266；沒有任何一張生成畫比最接近的驗證畫還近（`eval.json`，below_val_min = 0）。
- **順序不是被忽略，而是量過**：R1 用匈牙利配對把同層順序抹掉；我們量到亂序時下一筆的 x 學不會（loss 5.53 ≈ ln 256），也量到轉正後重排的效果。
- **離散 token 在油畫筆觸上為什麼能用，有直接證據**：試跑時 256 張 0 張能換算回圖（15% 的 token 落在錯的欄位），加上「每個欄位只在自己的範圍選」之後 256/256（devlog 2026-10-11）。⚠️ 這個修正跟 overlap 順序是同時加的，兩者的效果**沒有分開量過**。
- **資料來源**：R1 的訓練圖是 Stable Diffusion 生成的；我們是真照片加人工標的臉部點，沒有拿另一個生成模型的輸出來訓練。
- **兩個資料集之間的重複檢查**：AFHQ 驗證/測試貓沒有一隻是 CAT 訓練貓（最高相似 0.93，看過最像的五對）。十三篇都沒有報告這種檢查。
- **可重現**：每個版本的資料雜湊、權重雜湊、指令都有記錄；訓練可以從中斷處接著跑（測過結果一致）；一台筆電就能跑（R1 4 張 GPU、R11 A100、R4 64 張 V100）。

### 8.4 我們做了、十三篇都沒做的
1. **完全無條件、自迴歸、一筆一筆畫出有顏色、會疊色、由粗到細的油畫式動物**（第 5 節第 1 點）。
2. **用獨立的結構評審量「部位畫對了沒」**：眼睛評審（只在照片上訓練過的貓臉關鍵點模型），以及真畫切在每個階段的眼睛分數（0.429 / 0.495 / 0.527 / 0.537）。
3. **先寫構圖計畫再畫**：18 個臉部點 token 放在最前面，量過效果（眼睛比 D 0.84 → E 0.87；I 0.91）。
4. **把筆畫跟著臉一起轉正、縮放**，再在轉正後重排順序，並量過重排的效果（I 在 CAT 驗證貓上 3.9491 → 3.9407）。
5. **眼睛周圍的 loss 加重**，並量過（F、G、I）。
6. **把「接著畫」拆成每一層各自的貢獻，而且跟逐 token loss 對照**（2026-10-16，run I，64 隻 AFHQ 驗證貓）：
   真畫的最細兩層（160 + 360 筆）讓眼睛分數再加 0.042，模型畫的同兩層只加 0.005 ± 0.011；
   只讓它畫最後 360 筆時，畫完比不畫低 0.009 ± 0.007。但逐 token loss 最低的正是最後一層（3.80，第 0–1 層 4.15 / 4.17）。
   R1 的 Level 任務只報每一層的 FID，沒有拆每一層「加了多少」，也沒有跟 loss 對照。
   → **「loss 低的地方，畫面不一定對」是可以寫進論文的發現**（目前只有一個模型、一個種子，要等 J 再確認）。
7. **放進遊戲裡即時畫**：貓收容所每隻貓在 CPU 上約 13–14 秒畫完。這是應用，不是研究貢獻。

## 9. 小測驗

1. R1 的離散 token 基準線無條件 FID 是 320.43，他們自己的擴散模型是 30.12。為什麼這**不能**證明「我們的離散 token 模型一定不行」？用一句話說出兩邊實驗的關鍵差別。
2. PaintCopilot 的「接著畫」跟我們的「從零畫」，哪一個在生成每一筆時看得到「答案」？那個答案是從哪裡來的？
3. AttentionPainter 的 Stroke-density Loss 能讓眼睛畫得更好，為什麼我們現在不建議用？要用的話，會改到流程的哪一步？

<details><summary>參考答案</summary>

1. 他們的離散 token 模型是遮罩填空（BERT / MaskGIT，一次猜很多個被遮住的 token），我們是一個接一個猜的自迴歸，而且每個位置只在該欄位的 token 裡選；兩邊的資料、筆順也不同，所以不是同一個實驗。
2. PaintCopilot。它的每一筆會被最佳化去貼近「目標圖」，目標圖來自它的目標預測器（從目前畫布猜）、使用者上傳的參考圖，或外部的圖像生成 API。
3. 它改的是「畫家」（catbrush，把照片變成訓練用的筆畫），所以要把一萬多隻貓重畫；而且真畫的眼睛分數已經不低（0.537），眼睛不好的主因是模型生成，不是資料。
